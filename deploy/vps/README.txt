masquevpn — установка на VPS
========================

Что в папке
-----------
  vpnserver-amd64   сервер для x86_64
  vpnserver-arm64   сервер для aarch64
  install.sh        установка
  diag.sh           диагностика: собирает всё в diag.log
  uninstall.sh      удаление
  README.txt        это описание

Go на сервер ставить не надо: бинарники собраны заранее.


Два способа установки
---------------------
Разница в одном: занят ли на сервере TCP/443.

  A. Сервер пустой. masquevpn берёт TCP/443 и свои UDP-порты, сам получает
     сертификат у Let's Encrypt и сам показывает сайт-прикрытие.

  B. На TCP/443 уже стоит веб-сервер (nginx, Caddy, Apache) и трогать его
     нельзя. masquevpn берёт ТОЛЬКО UDP — туннелю нужен именно он, QUIC
     живёт поверх UDP. Сосед остаётся на TCP, отдаёт свой сайт и обновляет
     сертификат; masquevpn читает тот же сертификат из файлов.

Способ Б не уступает первому, а в одном месте даже лучше: прикрытием
становится настоящий сайт соседа, а не наш встроенный.


Что нужно до установки
----------------------
  1. Домен, A-запись которого УЖЕ указывает на этот сервер.

  2. Свободные UDP-порты — и в файрволе провайдера, и на самом сервере.
     Это сам транспорт туннеля. По умолчанию берётся набор
     443 8443 2053 2083 2087 2096 (см. «Порты» ниже); занятые порты из
     набора скрипт пропускает сам. Проверить:

         ss -lnu | grep -E ":(443|8443|2053|2083|2087|2096) "

  3. Для способа А — свободный 443/tcp: по нему приходит проверка
     Let's Encrypt (tls-alpn-01), и по нему же домен отдаёт обычный HTTPS.
     Домен с HTTP/3, но без HTTPS по TCP — заметная аномалия, видимая
     одним curl.

     Для способа Б — пути к сертификату соседа, обычно:

         /etc/letsencrypt/live/ВАШ.ДОМЕН/fullchain.pem
         /etc/letsencrypt/live/ВАШ.ДОМЕН/privkey.pem


Установка
---------
  scp -r masquevpn-vps root@ВАШ.СЕРВЕР:/tmp/
  ssh root@ВАШ.СЕРВЕР
  cd /tmp/masquevpn-vps

  # способ А — пустой сервер
  sudo sh install.sh ВАШ.ДОМЕН почта@пример.рф

  # способ Б — рядом с чужим веб-сервером
  sudo sh install.sh ВАШ.ДОМЕН \
      --cert /etc/letsencrypt/live/ВАШ.ДОМЕН/fullchain.pem \
      --key  /etc/letsencrypt/live/ВАШ.ДОМЕН/privkey.pem \
      --cover http://127.0.0.1:8080

(«sh install.sh», а не «./install.sh» — при копировании права на запуск
часто теряются, а так это неважно.)

До первого изменения в системе скрипт показывает, что именно собирается
сделать, и ждёт подтверждения.

Способ А, первый запуск, идёт на STAGING Let's Encrypt: сертификат
получится невалидным, зато проверяется весь путь его получения, а лимиты
там мягкие. Убедившись, что выдача проходит, повторите с боевым центром:

  sudo rm /etc/masquevpn/server.json
  sudo sh install.sh ВАШ.ДОМЕН почта@пример.рф --production


Порты
-----
Провайдеры режут UDP по номеру порта, не глядя в содержимое: бывает, что
UDP/443 не проходит вовсе, а 8443 проходит. Поэтому masquevpn слушает
несколько UDP-портов, а клиент перебирает их сам: не ответил один за
5 секунд — пробует следующий, а удачный запоминает (и после перезапуска
начинает с него). Если порт начнут резать посреди работы, клиент заметит
это за ~10 секунд и сам перейдёт на следующий, сохранив адрес в туннеле. Если не ответил ни
один, клиент так и пишет: «порты … не отвечают: закрыты по пути или сервер
выключен», а не непонятный таймаут.

  --ports default               стандартный набор: 443 8443 2053 2083 2087 2096
                                (так же без ключа на новой установке)
  --ports 8443,2053,2083        свой список; первый — основной
  без --ports при обновлении    порты остаются как были

Сменить порты позже:

  sudo vpnserver ports -config /etc/masquevpn/server.json                 показать
  sudo vpnserver ports -config /etc/masquevpn/server.json -set 8443,2053  записать
  sudo systemctl restart masquevpn

Если на машине включён ufw или firewalld, установщик откроет порты в нём
сам. Файрвол в панели хостинга он не видит — там порты надо открыть
руками (UDP, входящие).

Клиент узнаёт порты из ссылки: clients add дописывает их к адресу сам
(ВАШ.ДОМЕН:8443 → ВАШ.ДОМЕН:8443,443,2053,…). Порт из -server идёт первым —
укажите тот, что у ваших клиентов обычно проходит. Выданные раньше ссылки
знают только свой порт: чтобы клиент мог уходить на запасные, перевыдайте
доступ. Адрес с несколькими портами понимают клиенты 0.4.0 и новее; для
старого клиента — clients add ... -single-port.


Про --cover в способе Б
-----------------------
Снаружи домен один, а отвечают на него двое: сосед по TCP и masquevpn по UDP
(HTTP/3). Если не указать --cover, masquevpn покажет свой встроенный сайт, и у
одного домена окажется разное содержимое по TCP и по QUIC. Для того, кто
ищет туннели, это готовая примета.

Лечится тем, что masquevpn показывает сайт соседа. Взять его можно только с
локального порта — тот, что на 443, занят TLS соседа. В nginx это лишний
блок; 443 при этом не трогается:

    server {
        listen 127.0.0.1:8080;
        server_name ВАШ.ДОМЕН;
        ... тот же root / proxy_pass, что и в блоке на 443 ...
    }

    nginx -t && systemctl reload nginx

После этого --cover http://127.0.0.1:8080 — и оба пути показывают одно и
то же. Если 8080 уже поднят, скрипт найдёт его сам.

Обновление сертификата отдельных действий не требует: certbot перезапишет
файлы, masquevpn заметит это в течение полуминуты и начнёт отдавать новый —
без перезапуска службы.


После установки
---------------
  journalctl -u masquevpn -f                               журнал
  vpnserver clients list -config /etc/masquevpn/server.json клиенты
  sudo cat /etc/masquevpn/client-first.link  доступ первого клиента (ссылка)
  sudo sh diag.sh                            диагностика → diag.log

Доступ первого клиента — ссылка masquevpn://… в client-first.link (и то же
самое в виде client.json — client-first.json). Ссылка и есть ключ: не
пересылайте её открыто. В приложении: «+» → «Вставить из буфера».

Ещё клиенты заводятся так:

  sudo vpnserver clients add -config /etc/masquevpn/server.json \
       -name "телефон" -server ВАШ.ДОМЕН:8443 -quota 200GB -max-sessions 4 \
       -out /root/телефон.json

Отозвать доступ:

  sudo vpnserver clients disable -config /etc/masquevpn/server.json -id ПСЕВДОНИМ

Сервер перечитывает реестр сам (раз в 10 секунд) и закрывает живые сессии
отозванного — перезапускать его не нужно.


Что беречь
----------
  /etc/masquevpn/clients.json     ключи всех клиентов
  /var/lib/masquevpn/acme/        ключ аккаунта ACME и сертификаты

Потеря первого отключает всех клиентов, потеря второго заставляет
перезаказывать сертификат. Оба файла стоит держать в бэкапе.
uninstall.sh без --purge их не трогает.


Если что-то не так
------------------
Запустите diag.sh и посмотрите diag.log — секретов он не собирает, ключи
и содержимое реестра туда не попадают. Самые частые причины:

  служба не стартует       → порт занят или конфигурация не прошла проверку
  сертификат не приходит   → A-запись не на этот сервер, либо 443/tcp
                             закрыт файрволом провайдера
  клиент не подключается   → ключ или псевдоним не от этого сервера,
                             либо разъехались часы (токен привязан ко времени)
  туннель есть, интернета нет → не включён ip_forward или нет NAT;
                             это видно в разделе «сеть» файла diag.log


Сервер, поставленный до переименования (govpn)
----------------------------------------------
Просто запустите новый install.sh так же, как в первый раз. Он найдёт
/etc/govpn, сохранит копию в /root/govpn-backup-<время>.tar.gz (там ключи
всех клиентов — храните её как сами ключи), перенесёт данные в
/etc/masquevpn и /var/lib/masquevpn, заменит службу govpn на masquevpn и
оставит ссылку /etc/govpn → /etc/masquevpn для старых команд. Выданные
доступы продолжают работать: ключи и адрес сервера не меняются.
