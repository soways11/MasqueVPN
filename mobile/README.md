# Мобильный клиент masquevpn

Ядро (`mobile/core`) — это тот же Go-код, что работает на Linux и Windows:
протокол, маскировка, ротация, переподключение, реестр клиентов. Отличается
только то, кто создаёт сетевой интерфейс. На desktop это делает сам клиент
(`internal/netsetup`), на телефоне — система, а приложение получает от неё
готовый файловый дескриптор.

## Порядок вызовов

На Android есть неприятность, из-за которой запуск разделён надвое.
`VpnService.Builder` требует адрес **до** создания интерфейса, а наш адрес
выдаёт сервер капсулой ADDRESS_ASSIGN уже **внутри** установленной сессии.
Курица и яйцо. Поэтому:

```
Connect(config, protector, events) → JSON с адресами, маршрутами, DNS и MTU
        ↓                    приложение строит VpnService.Builder по этому JSON
        ↓                    establish() → дескриптор
Attach(fd)                   ядро начинает перекачку пакетов
```

Если сервер потом выдаст другой адрес (аренда истекла и прежний ушёл в пул),
ядро зовёт `Events.OnRebind`: интерфейс надо построить заново и отдать новый
дескриптор в `Rebind`. Сессия при этом **не рвётся**, поэтому соединения
внутри туннеля переживают перестройку. При обычной ротации этого не
происходит: адрес закреплён за клиентом арендой.

`Protector.Protect(fd)` — это `VpnService.protect`. Без него пакеты самого
туннеля пойдут **в** туннель, и он замкнётся сам на себя. Ядро считает отказ
защиты ошибкой и не продолжает: молчаливый вариант выглядел бы как «просто
не работает».

## Экраны

Три экрана, в том же стиле, что окна Windows и Linux:

- **Главный** — состояние, кнопка «Подключиться», скорости, счётчики
  (принято, отправлено, сессия), профили с меню «⋯» (сделать выбранным,
  переименовать, изменить, скопировать ссылку, удалить), журнал.
- **Добавить сервер** (кнопка «+») — адрес, ключ, идентификатор, имя;
  «Вставить из буфера» раскладывает ссылку `masquevpn://` по полям. Экран
  открывается и нажатием на такую ссылку в мессенджере, если тот делает её
  нажимаемой.
- **Настройки** — «Аварийное отключение» ведёт в системные настройки VPN
  (на Android его делает система: «Постоянный VPN» и «Блокировать соединения
  без VPN»), добавление сервера, псевдоним устройства, версия.

Нарисованы своими средствами Android (View и XML) — так работают
клавиатура, TalkBack и системные отступы. Но цвета, размеры и кегли не
подобраны на глаз, а **сгенерированы из `internal/gui`** — той же палитры,
которой рисуют окна (`res/values/colors.xml`, `dimens.xml`,
`text_styles.xml`; руками не править, см. заголовок файлов). Тексты — те же
строки. Числа («1,24 ГБ», «38 Мбит/с», «04:12») форматирует ядро тем же
кодом, что и в окнах, а правила формы (что считать ошибкой и какое поле
подсветить) — те же `config.BuildForm` и `config.ParseShared`.

## Сборка

### Windows

```powershell
powershell -ExecutionPolicy Bypass -File mobile\build-apk.ps1
```

Скрипт сам найдёт SDK и NDK, поставленные Android Studio, поставит
`gomobile` нужной версии, соберёт ядро и приложение.

### Linux и macOS

Нужны Android SDK и NDK: `gomobile` связывает Go с Java через cgo. Проще
всего поставить Android Studio, а в её SDK Manager добавить Platform 35, NDK
(Side by side) и Build-Tools.

```sh
export ANDROID_HOME=$HOME/Android/Sdk           # macOS: $HOME/Library/Android/sdk
export ANDROID_NDK_HOME=$ANDROID_HOME/ndk/<версия>

./mobile/build-apk.sh    # оба шага: core.aar + APK
```

Скрипт делает две вещи по очереди: `build-aar.sh` собирает ядро
(`gomobile bind` → `mobile/android/app/libs/core.aar`), затем
`./gradlew assembleDebug` собирает приложение. Готовый APK —
`mobile/android/app/build/outputs/apk/debug/app-debug.apk`.

Отдельными шагами — если нужно пересобрать только одно:

```sh
./mobile/build-aar.sh                        # только ядро
cd mobile/android && ./gradlew assembleDebug # только приложение
```

Gradle-wrapper в репозитории есть (`gradlew`, `gradle/wrapper/`), так что
отдельно ставить Gradle не нужно — первый запуск сам скачает нужную версию.
`core.aar` не лежит: это собираемый артефакт на несколько десятков мегабайт
(исключён в `.gitignore`).

Открыть проект в Android Studio (`mobile/android`) и нажать Run — тоже
рабочий путь; `core.aar` при этом всё равно нужно собрать заранее
`build-aar.sh`, потому что его делает Go, а не Gradle.

## Конфигурация

Та же, что у desktop-клиента, с двумя оговорками:

- `tun.name` и `full_tunnel` влияют только на то, **что ядро попросит** у
  системы; настраивает всё равно она.
- резолверы для прикрытия DNS задавать не нужно: приложение подставляет
  системные само (см. ниже). Если всё же задать `dns_cover.servers` вручную,
  подставленное не перезапишет их.

Ключ и псевдоним берутся с сервера: `vpnserver clients add -name "телефон"`.

## Что приложение делает само

Три вещи, которых ядро сделать не может, и без которых клиент был бы
неполным:

- **Резолверы системы для прикрытия DNS.** Ядро на desktop берёт их из
  `resolv.conf`, а на Android читать неоткуда. Приложение достаёт их через
  `ConnectivityManager` и кладёт в конфигурацию ДО подключения — важно взять
  их, пока активна обычная сеть, а не туннель. Без этого прикрытие молча не
  включается, то есть одна из мер против DPI просто не работает.
  Заданные вручную `dns_cover.servers` не трогаются.
- **Постоянный VPN (always-on).** Систему не интересует наш экран: она
  поднимает службу сама — при включённом «постоянном VPN» и после
  перезагрузки, — и Intent тогда пуст. Поэтому конфигурация живёт в
  хранилище приложения, и служба читает её оттуда всегда.
- **Псевдоним устройства.** По одному ключу работают несколько устройств, и
  сервер закрепляет адрес за парой «клиент + устройство». На desktop псевдоним
  берётся из файла рядом с программой, на телефоне — случайная строка в
  хранилище приложения, созданная один раз. В резервную копию она не
  попадает: восстановленная на другом телефоне копия дала бы двум устройствам
  один адрес.
- **Запрос разрешения на уведомления.** На Android 13+ уведомление службы без
  этого молча не показывается, а для VPN оно не украшение: это единственный
  видимый признак, что туннель поднят, и кнопка «Отключить» в нём. Приложение
  просит разрешение один раз при первом открытии; отказ не мешает работе.

## Что проверено, а что нет

**Проверено на стенде из трёх network namespace** (`test/e2e`,
`TestAndroidCoreOnStand`, `TestAndroidSurvivesRotation`,
`TestAndroidWithoutProtectLoopsOnItself`). Роль системы играет
`test/e2e/androidsim`: он сам открывает TUN, отдаёт ядру голый дескриптор,
настраивает интерфейс по тому же JSON, который увидит Kotlin, и защищает
сокет — меткой вместо `protect`. То есть проверяется не похожий путь, а тот
же самый, кроме двух системных вызовов.

**Проверено отдельно: API связывается.** `gomobile bind` требует NDK, но
`gobind` — чистый Go, и он сгенерировал привязки к Java прямо здесь. Значит
проверено то, что иначе всплыло бы только на машине со сборкой Android:
экспортированные типы связываются, а вызовы из Kotlin совпадают с
получившимися сигнатурами (сверено механически). Подробности и сам список
сигнатур — в `core/BINDINGS.md`.

**Проверено без SDK: приложение.** `mobile/androidcheck`:

- каждая ссылка на ресурс в XML и каждый `R.*` в Kotlin существуют;
  `findViewById` ищет идентификатор в разметке своего экрана; классы из
  манифеста есть в исходниках; вызовы ядра есть в привязке (`BINDINGS.md`);
- **Kotlin компилируется** настоящим `kotlinc` против Java-привязки ядра от
  gobind и заглушек Android API (`androidcheck/stubs` — только то, что
  вызывает приложение, с сигнатурами из документации). Ловит Long вместо Int
  у gomobile, забытые импорты, неверное число аргументов. Запуск — в
  начале `androidcheck/typecheck_test.go`.

**Не проверено:** сборка `core.aar` (нужен NDK) и самого приложения (нужны
Android SDK и зависимости Gradle): ресурсы проверяет только aapt2, а
заглушки Android могут расходиться с настоящим API. В этом окружении `dl.google.com` и
Maven Central закрыты политикой сети, так что оба шага делаются на машине с
обычным доступом. Первый запуск на телефоне — отдельный шаг: там всплывёт то,
чего стенд не покажет, — согласие на VPN, поведение в Doze, смена Wi-Fi на
мобильную сеть.
